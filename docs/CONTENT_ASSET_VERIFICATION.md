# 본문 파일 공개 검증

`npm run test:content-assets`는 세 게시글 유형에서 상태 전환, 파일 추가·교체·제거·공유, 비공개 연결의 복구, 잘못된 파일 ID와 외부 주소 제외, 반복 실행과 설치 순서를 확인합니다.

실제 이벤트와 파일 권한 검증은 운영과 분리된 빈 Directus 11.3.5에서 실행합니다. 테스트가 컬렉션·권한·플로우와 작은 테스트 PNG를 생성하므로 운영 CMS에서 실행하지 않습니다.

1. 별도 임시 SQLite DB와 uploads 경로로 Directus를 초기화합니다. 테스트 관리자 이메일은 `assets@example.com`, 비밀번호는 `local-assets-test-password`를 사용합니다. 실제 계정을 사용하지 않습니다.
2. `HOST=127.0.0.1 PORT=8059 PUBLIC_URL=http://127.0.0.1:8059`로 테스트 CMS를 실행합니다.
3. `node tests/content-assets.integration.mjs`를 실행합니다. 다른 로컬 포트는 `TEST_DIRECTUS_URL`로 지정합니다. 스크립트는 `127.0.0.1` 이외의 호스트를 거부합니다.

다음 케이스를 교회 이야기·주보·공지에서 각각 실행하고, 인증 없는 `/assets/:id` 응답으로 확인합니다.

| 케이스 | 예상 |
| --- | --- |
| 업로드만 수행 또는 임시 저장 | 403 |
| 임시 저장 → 게시 | 200 |
| 보관 → 게시 | 200 |
| 처음부터 게시 상태로 작성 | 200 |
| 게시글에 사진 추가·교체 | 새 사진 200, 다른 공개 참조가 없는 이전 사진 403 |
| 여러 게시글에서 같은 파일 사용 | 하나가 비공개여도 나머지가 공개면 200 |
| 마지막 공개 참조 삭제·비공개 전환 | 403 |
| 파일 연결이 draft인 상태에서 재게시 | 200 |
| 플로우 재설치 | 같은 플로우·작업을 갱신하고 중복 생성하지 않음 |
| 중간관리자로 게시·보관 | 기존 콘텐츠·파일 권한만 사용해 정상 처리 |
| 플로우 구성 갱신 실패 | 이전 활성 플로우와 작업을 복구 |

운영 복구 시에는 공개 게시글의 참조 파일만 `content_assets`에 등록하고, 로그인하지 않은 상태에서 원본과 목록용 이미지 요청을 확인합니다. 관리자 화면에서 사진이 보이는 것만으로 공개 복구를 판단하지 않습니다.
